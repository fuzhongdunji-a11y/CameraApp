【変更内容まとめ】緑色判定の厳格化および低比率時の動作修正

1. InferencePipeline.java の変更
■ 閾値の変更と推論のスキップ
緑色の割合が閾値（25%）未満の場合、AI推論を実行せずにラベルを "Low Green"、スコアを 0.0% に固定するようにしました。

```java
public Result process(Bitmap bitmap, int cellIndex, boolean shouldSaveImage) {
    float greenRatio = calculateGreenRatioFast(bitmap);
    String label;
    float confidence;

    if (greenRatio < config.getGreenThreshold()) {
        label = "Low Green";
        confidence = 0.0f; // 判定不足時はスコアを0に固定
    } else {
        ClassificationResult classResult = classifier.classify(bitmap);
        label = classResult.getLabel();
        confidence = classResult.getConfidence();
        // ... 保存処理 ...
    }
    return new Result(label, confidence, imagePath, greenRatio);
}
```

■ 緑色判定ロジックの厳格化
土の茶色やグレーの背景を誤検知しないよう、HSV表色系とExG指標を組み合わせた判定に変更しました。
- Hue(色相): 80-160 (純粋な緑)
- Saturation(彩度): 0.50以上 (鮮やかな緑のみ)
- G > R * 1.25, G > B * 1.15 (緑成分の優位性)

2. PlantClassifier.java の変更
■ 信頼度（スコア）の調整
判定が常に99%以上に張り付くのを防ぐため、温度スケーリング（TEMPERATURE）を 2.5f から 5.0f に引き上げ、数値をマイルドにしました。

```java
private static final float TEMPERATURE = 5.0f;
```

3. ResultRepository.java の変更
■ ステータス更新のフィルタリング
"Low Green"（緑不足）の判定結果を受け取った際、その区画のステータスを「健康(OK)」に更新しないように制限しました。

```java
public void add(CellResult record) {
    // ...
    if (record.getResult().toLowerCase().contains("low green")) {
        return; // 緑不足時はマップのステータス(OK/NG)を更新しない
    }
    // ...
}
```

4. 閾値の設定変更
プロジェクト全体で緑色の判定閾値を 60% から 25% に変更しました。
- InferencePipeline.java: 閾値デフォルト値を 0.25f に変更。
- MainActivity.java: UI表示上の閾値表記を 0.25 に更新。


【変更内容まとめ】YOLOで切り出した植物領域を分類モデルに渡す処理を復活（2026-11-10）

1. YoloDetector.java の変更
■ 入力データの並び順を修正
モデルの入力は [1, 3, 640, 640]（チャンネルが先）なのに、RGBRGB... と画素ごとに並べて渡していたため、モデルに正しい画像が届いていませんでした。R の全画素 → G の全画素 → B の全画素 の順に並べるように修正しました。
- 修正前: 最高スコア 0.02 程度（そのためスコアのしきい値が 0.005 になっていた）
- 修正後: ピーマン画像で 0.77 など正常な値（PC で同じモデルを動かして確認）

```java
for (int v : intValues) buffer.putFloat(((v >> 16) & 0xFF) / 255f); // R
for (int v : intValues) buffer.putFloat(((v >> 8) & 0xFF) / 255f);  // G
for (int v : intValues) buffer.putFloat((v & 0xFF) / 255f);         // B
```

■ letterbox 前処理と座標の変換
- アスペクト比を保ったまま 640x640 に収め、余白を灰色(114)で埋めるように変更しました。
- 検出枠の座標を元画像のピクセル座標に戻して返すようにしました（以前は 640x640 の座標のままで、元画像で切り出すと位置がずれていた）。
- スコアのしきい値を 0.005 から 0.25 に変更しました。

2. CropUtils.java の変更
■ 余白付きの切り出し
検出枠の周囲を指定した割合だけ広げて切り出す crop(bitmap, det, margin) を追加しました。

3. InferencePipeline.java の変更
■ 判定の流れ
1) YOLO で検出した枠をスコアの高い順に（最大5件）、上下左右 10% 広げて切り出す。
2) 切り出した領域の緑比率が 15% 以上なら植物領域とみなし、その画像を分類モデルに渡す。
   公開 YOLO モデル（COCO 学習）はピーマンを apple と判定するなどクラス名が当てにならないため、クラスでは絞らず緑色かどうかで判断する。短辺 64px 未満の枠は使わない。
3) 植物領域が見つからない場合は、従来どおり画面全体の緑比率が 25% 以上なら画面全体を判定する。
4) どちらも満たさない場合は従来どおり "Low Green" として判定しない。

```java
PlantCrop crop = config.isUseYoloCrop() ? findPlantCrop(bitmap) : null;
if (crop != null) {
    classResult = classifier.classify(crop.bitmap);   // YOLO 切り出し画像で判定
} else if (config.isFullFrameFallback() && frameGreenRatio >= config.getGreenThreshold()) {
    classResult = classifier.classify(bitmap);        // 画面全体で判定
} else {
    label = "Low Green"; confidence = 0.0f;           // 判定しない
}
```

■ 設定と結果の追加
- Config: useYoloCrop（切り出しを使うか）、fullFrameFallback（画面全体へのフォールバック）、cropGreenThreshold（切り出し領域の緑比率しきい値、既定 0.15）
- Result: 判定対象（YOLO切り出し／画面全体／なし）、YOLO の検出スコア、検出枠
- 保存する画像は従来どおり画面全体。

4. MainActivity.java の変更
■ 表示の追加
- 結果表示に「判定対象: YOLO切り出し (検出スコア x.xx) / 画面全体 (植物領域の検出なし)」を追加しました。
- 病気フレームかどうか・「緑不足」表示の判定を result.isClassified() で行うように変更しました。
